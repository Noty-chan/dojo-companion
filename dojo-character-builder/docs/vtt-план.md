# Виртуальный стол «Паника в Додзе» — подготовительный план

Цель: упрощённый виртуальный стол в духе Foundry, но заточенный только под PatD
(клетки-арена, стойки, кости действий, жетоны), связанный с компаньоном: персонажи
и сцены **импортируются из него**, а не создаются заново.

## Что уже готово в компаньоне под VTT

- **Стабильные версионированные форматы обмена** (см. «Контракт данных» ниже):
  герой, враг, сцена, пачка игроков — JSON с полем `type` и `schemaVersion`.
  Импортёр компаньона различает их по `type`; VTT должен делать так же.
- **PNG-карточки с зашитым JSON** (`portablePng.ts`) — тот же контракт, но в виде
  картинки; VTT может принимать их тем же кодом.
- **Supabase-слой** (`src/utils/cloud.ts` + `supabase/schema.sql`): auth и база уже
  настроены; у Supabase есть **Realtime-каналы** — это готовый транспорт для
  синхронизации стола (позиции фишек, HP, ход) без собственного сервера.
- **Резолверы правил**: `utils/enemyResolve.ts` (кости/преимущества врагов по уровню),
  `utils/build.ts` (валидация героя), `utils/enemy.ts` (масштабы, жетоны) — VTT
  переиспользует их как пакет, а не копирует.

## Контракт данных (не ломать!)

| `type` | Содержимое | Создаёт |
|---|---|---|
| `panic-at-the-dojo.character` / `character-card` | `build: CharacterBuild` (schemaVersion 2) | Герои → экспорт |
| `panic-at-the-dojo.enemy-build` / `enemy-card` | `build: EnemyBuild` (schemaVersion 1) | Мастерская → Враг |
| `panic-at-the-dojo.encounter` / `encounter-card` | `scene: SceneState`, `roster: EnemyBuild[]`, `current` | Мастерская → Сцена |
| `panic-at-the-dojo.party` | `party: Party`, `heroes: SavedHero[]` (билды внутри) | Мастерская → Герои → пачка |

Правила эволюции: новые поля — только опциональные; смена смысла поля = +1 к
`schemaVersion` и поддержка чтения старой версии в импортёрах обоих приложений.

## Архитектура VTT (набросок)

- **Отдельное приложение** в этом же духе (Vite + React + TS), например `dojo-table/`,
  переиспользующее `types.ts` и резолверы (вынести общий код в `packages/` или
  простыми относительными импортами — решить при старте).
- **Комната = строка в Supabase** (`dojo_rooms`): ГМ создаёт комнату из сцены
  компаньона, игроки входят по коду комнаты; состояние стола — jsonb + Realtime-канал.
- **Поле боя**: квадратная сетка (арены PatD маленькие, ~8×8), фишки героев/врагов,
  зоны/препятствия/ямы как раскраска клеток. Никакого fog of war, стен, освещения —
  PatD это не нужно.
- **Панель хода**: стойка (форма+стиль), бросок пула костей действий, трекеры HP/щит/
  броня/жетоны — те же компоненты, что в игровом листе компаньона.
- **Discord-вебхук** комнаты: бросок/итог хода можно дублировать в канал (модуль
  `utils/discord.ts` уже умеет).
