# Хостинг, аккаунты и Discord — как всё включить

Компаньон остаётся полностью рабочим офлайн. Три онлайн-возможности включаются независимо друг от друга:

| Возможность | Что нужно | Где настраивается |
|---|---|---|
| Сайт на GitHub Pages | GitHub-аккаунт + `gh auth login` | `npm run deploy:pages` |
| Discord-вебхуки | ссылка вебхука канала | в приложении: Экспорт / импорт → «Discord-вебхук» |
| Аккаунты и облако | бесплатный проект Supabase | в приложении: Экспорт / импорт → «Аккаунт и облако» |

---

## 1. Сайт на GitHub Pages — УЖЕ РАЗВЁРНУТ (2026-07-04)

- **Компаньон:** https://noty-chan.github.io/dojo-companion/
- **Стол (VTT):** https://noty-chan.github.io/dojo-companion/table/

Публикуется **только собранное приложение** (`dist/` обоих приложений), а не репозиторий
перевода — PDF книги и черновики наружу не попадают. Репозиторий: `Noty-chan/dojo-companion`
(публичный, ветка `gh-pages`).

**Обновить сайт** после правок — из папки `dojo-character-builder`:
```
npm run deploy:pages
```
Скрипт соберёт компаньон и стол (нужен Python для генерации данных — как обычно),
запушит их в `gh-pages` (компаньон в корень, стол в `/table/`) и убедится, что Pages включён.
GitHub CLI должен быть авторизован (`gh auth status`; при необходимости — `gh auth login`).

**Любой другой статический хостинг** тоже подходит: содержимое `dist/` можно положить
на Netlify, Cloudflare Pages, свой nginx — приложение собрано с относительными путями.

⚠️ Помните: в `builder-data.json` зашит переведённый текст правил. Публичная ссылка =
публичный текст. Если это нежелательно, держите ссылку «серой» (не индексируется, но
доступна всем, у кого она есть) или используйте приватный хостинг.

## 2. Discord-вебхуки (без сервера)

Вебхуки Discord принимают сообщения прямо из браузера, бэкенд не нужен.

1. В Discord: настройки канала → **Интеграции** → **Вебхуки** → «Создать вебхук» → «Копировать URL».
2. В компаньоне: **Экспорт / импорт** → панель «Discord-вебхук» → вставить ссылку → «Тестовое сообщение».
3. После этого работают кнопки «В Discord»:
   - **герой** — Экспорт / импорт → «Герой → Discord»;
   - **враг** — Мастерская → Враг → «Готовый блок»;
   - **сцена** — Мастерская → Сцена → панель действий;
   - **пачка игроков** — Мастерская → Герои → панель пачки.

Ссылка вебхука хранится только в localStorage этого браузера. Кто знает ссылку — может
писать в канал, поэтому не публикуйте её.

## 3. Аккаунты и облачная синхронизация (Supabase)

Позволяет переносить весь прогресс (герои, пачки, сцены, пресеты, текущий билд) между
устройствами. Работает на бесплатном тире Supabase.

**Проект уже настроен и прошит в приложение (2026-07-03):** схема применена, комнаты
стола и хранилище фонов включены. Пользователям ничего вставлять не нужно — панель
«Аккаунт и облако» сразу предлагает вход/регистрацию (почта + пароль).

- **«В облако»** — сохранить текущее состояние; **«Из облака»** — заменить локальное
  состояние облачной копией (спрашивает подтверждение).
- **Важно про регистрацию (иначе письмо ведёт на localhost:3000).** У свежего проекта Supabase
  «Site URL» = `http://localhost:3000`, и ссылка из письма-подтверждения возвращает туда, а не в
  приложение. Есть два способа это убрать (достаточно любого):
  1. **Проще всего — выключить подтверждение почты:** дашборд Supabase → **Authentication →
     Sign In / Providers → Email** → выключить **«Confirm email»**. Тогда регистрация входит сразу,
     без письма и без редиректа. Для игрового инструмента это удобнее всего.
  2. **Или задать адрес приложения:** дашборд → **Authentication → URL Configuration** →
     **Site URL** = `https://noty-chan.github.io/dojo-companion/`, и в **Redirect URLs** добавить
     `https://noty-chan.github.io/dojo-companion/**`. Тогда письмо вернёт пользователя в приложение
     и вход подхватится сам. (Приложение уже просит вернуть на свой адрес через `emailRedirectTo`,
     но адрес должен быть в этом списке разрешённых.)
- Аккаунт, который уже создан и подтверждён, работает сразу — достаточно нажать **«Войти»**
  (не «Зарегистрироваться») с той же почтой и паролем.
- Publishable-ключ публичен по замыслу Supabase; чужие данные защищены политиками
  Row Level Security из `supabase/schema.sql` (каждый видит только свою строку).
- Чтобы использовать **другой** проект: создать его на supabase.com, выполнить там
  `schema.sql`, затем в панели «Отвязать проект» и ввести свои URL + ключ.
  Схему можно накатывать повторно — она идемпотентна.

### Ограничения текущей версии

- Синхронизация ручная (push/pull целиком), не автоматическая и не построчная.
- Общий доступ «ГМ видит героев игроков» пока делается через экспорт пачки JSON или
  Discord; realtime-обмен появится вместе с виртуальным столом (см. `vtt-план.md`).
